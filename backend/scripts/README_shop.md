# 演示商城购物流程

本阶段提供可运行的购买流程，所有支付均为模拟支付，不接真实支付渠道，不发生真实扣款或自动呼叫快递服务。

## 使用

1. 普通用户登录，浏览全部商品或商品详情，立即购买或加入购物车。
2. 购物车支持调整数量、移除、多选、全选可购买商品；不同币种需分别下单。
3. 结算选择收货地址，可现场新增地址，填写收货人、联系电话、省市区、详细地址和可选邮编。个人中心可维护最多 20 个地址及默认地址。
4. 确认商品和金额后提交订单，可填写备注。演示订单运费为零。
5. 订单页模拟支付，或取消待支付订单。管理员在“订单管理”中录入快递公司和单号，用户可查看物流信息并确认收货。

页面：`/cart`、`/checkout`、`/addresses`、`/orders`、`/orders/{id}`、`/admin/orders`。

管理员在“商品管理”的“销售设置”中维护演示售价、币种、可售库存和是否上架。新增商品需另外设置销售价格并上架后才能购买。商品资料中的历史参考价仍独立保留。

## 数据库与初始化

项目根目录执行：

```powershell
& backend/venv/Scripts/python.exe backend/scripts/init_shop.py
```

可选 `--seed-demo-offers` 会为尚无销售设置的现有可展示商品创建演示售价（复制原币种历史参考价），演示初始库存 100；不会覆盖已存在的售价和库存。本地已执行，为 400 个商品建立演示销售设置，不代表真实报价或真实库存。

新增表：

| 表 | 用途 |
| --- | --- |
| sale_offers | 独立销售价格、币种、可售库存、上下架和版本时间 |
| cart_items | 用户购物车，用户与商品组合唯一 |
| shipping_addresses | 用户收货地址、联系人和默认地址 |
| shop_orders | 订单编号、所属用户、收货快照、总价、状态、有效期、物流和各阶段时间 |
| shop_order_items | 商品名称、图片、数量和单价快照 |

旧 `orders` 表里的演示数据不迁移、不删除，前端“我的订单”已切换到真实写入的 `shop_orders`。

## 状态和一致性

`pending_payment → paid → shipped → completed`

`pending_payment → cancelled`（用户取消或超时）

- 提交订单时锁定商品和销售设置，由服务端计算金额并扣减可售库存；购物车不占库存。
- 待支付有效期 30 分钟。访问购物车、结算或订单接口时批量清理超时订单并释放库存；当前采用请求触发清理，没有后台定时任务。无访问时不承诺恰好第 30 分钟更新状态。
- 结算只移除本次所选购物车条目，未选商品保留。直接购买不清理购物车。
- 订单包含创建时的商品、价格、图片引用、联系方式和地址快照；之后改商品、售价、地址或删除商品，不会改写旧订单。
- 提交请求携带 `request_key`，同一用户的同键同内容重试返回原订单，变更内容复用键会被拒绝。
- 服务端检查客户端确认过的价格、币种和数量；价格或购物车发生变化返回 409，需要重新确认。
- 同一用户的购物车和结算写入串行化，库存用数据库行锁防止超卖；取消、支付和收货按订单行锁检查合法状态。
- 用户只能访问自己的购物车、地址、订单；发货、销售设置和全部订单查询仅超级管理员可操作。

## 接口

用户接口位于 `/api/shop`，均需 Bearer JWT：

- `GET/POST /cart`，`PATCH/DELETE /cart/{id}`。
- `GET/POST /addresses`，`PUT/DELETE /addresses/{id}`。
- `POST /checkout/preview`：核价，无库存预占。
- `POST /orders`：原子下单，保留库存。
- `GET /orders`、`GET /orders/{id}`。
- `POST /orders/{id}/pay`：模拟支付。
- `POST /orders/{id}/cancel`、`POST /orders/{id}/complete`。

管理员接口位于 `/api/admin`：

- `GET/PUT /offers/{product_id}`，PUT 携带读取时的 `updated_at` 防止库存覆盖。
- `GET /orders`：分页、状态筛选和订单编号搜索。
- `POST /orders/{id}/ship`：仅已支付订单可发货，保存快递公司和快递单号。

## 验证与后续边界

`backend/tests/test_shop.py` 在独立临时 PostgreSQL schema 中验证越权、参数校验、选中条目结算、快照、重复请求、超时释放、状态流转和并发抢购，不向真实业务表写入测试订单。

真实支付需另外接入支付渠道及验签回调，不能沿用前端点击即支付的演示接口。实时物流查询、运费模板、优惠券、发票和真实资金退款仍需后续接入；模拟退款及售后工单流程见 README_aftersales.md。现有 Agent 已能只读查询这些订单、商品和本人浏览记录，但没有实际退款或支付执行工具。
