# 手动订单异常分析与客服待办

管理员入口：`/admin/tasks`。从订单管理的“分析订单 / 查看待办”也可直接进入并预选订单。商品运营助手不在本次范围内。

## 手动工作流程

1. 管理员选择订单，点击“分析所选订单”。只有点击后才核实该订单并调用异常跟进 Agent。
2. 页面展示分析、处理步骤和客户回复草稿。此时没有创建待办，也不修改订单或发送消息。
3. 管理员点击“确认创建待办”，服务端重新核实订单事实并创建任务。相同来源重复确认会返回已有待办。
4. 客服可认领、释放、备注、完成或忽略待办。完成/忽略必须填写说明，其他客服不能抢占已认领任务。
5. 可进入订单唯一的客户会话，复制建议后编辑并手动发送。人工客服助手可以查看关联待办。

没有后台定时扫描、全量扫描按钮、自动分析队列或自动创建待办。列表/详情刷新仅展示数据，不创建、分析或关闭待办。订单事实变化时旧建议不再展示，提示客服重新核实；待办仍由客服手动完成或忽略。

## 当前可分析的事项

- 已支付满 48 小时未发货，且无进行中售后。
- 发货满 7 天未确认收货，且无进行中售后；未接入承运商轨迹，不能据此断言丢件。
- 退款申请待审核满 24 小时。

这些是手动分析时使用的内部参考规则，不会主动运行。未命中时说明没有符合当前规则的事项，不创建待办。

## 数据与安全

执行 `python scripts/init_support_tasks.py` 创建或更新所需表。

- `support_tasks` 保存已有待办；`support_task_events` 保存处理记录，历史记录继续保留。
- `support_task_previews` 保存管理员生成的分析预览，30 分钟有效。确认时只接受服务端预览编号，不接受客户端自拟 AI 建议或身份。
- 仅超级管理员可访问；预览只能由生成它的管理员确认。订单变化、预览过期或被篡改时拒绝创建。
- 原有 `support_scan_state` 作为历史表保留，已无扫描功能使用它。原扫描环境变量不再生效。
- AI 不接收完整收货人、电话和详细地址；不修改订单、执行退款或自动发送消息。

## API

- `POST /api/admin/support-tasks/preview`：参数 `order_id`，分析选定订单，只生成预览。
- `POST /api/admin/support-tasks`：参数 `preview_id`，管理员确认后创建待办。
- `GET /api/admin/support-tasks/summary`：待办统计，`mode=manual`。
- `GET /api/admin/support-tasks`：分页筛选。
- `GET /api/admin/support-tasks/{id}`：只读详情及处理记录。
- `POST /api/admin/support-tasks/{id}/analyze`：手动重新分析已有待办。
- `POST /api/admin/support-tasks/{id}/actions`：认领、释放、备注、完成或忽略。
- `POST /api/admin/support-tasks/{id}/conversation`：创建或复用订单会话，不发送消息。

原 `/scan` 接口和后台调度器已移除。
